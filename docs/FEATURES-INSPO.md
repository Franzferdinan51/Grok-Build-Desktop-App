## Product choices made from the research

- **Local-first:** LM Studio is a real configuration surface and the app avoids model load commands by default.
- **Grok first:** every coding task is executed by Grok Build, not an Electron “sidecar agent.”
- **Official plan mode:** the composer Plan toggle and `/plan` send `--permission-mode plan` and omit `--no-plan`. The desktop reads `~/.grok/sessions/<encoded-cwd>/<id>/plan.md` for `/view-plan` instead of inventing a plan file.
- **Official workflows:** the Workflows page lists project and user `.rhai` scripts. Launch is `grok -p "/workflow <name>"`. Duck-Agent plan/research/code/operate remain prompt presets only when the name is not a discovered Rhai script.
- **Telegram:** implemented as an encrypted, explicit bot connection. No inbound auto-run without an allowlist.
- **Visual direction:** a dark, compact coding workbench inspired by the supplied MiniMax screenshot, without copying its plan/upsell UI or assets.
- **Duck-Agent integration boundary:** the Project Files rail is intentionally a focused UI integration. It reuses the app's existing workspace file listing and editor handoff, so the desktop remains Grok Build-primary and does not import Duck-Agent's separate React runtime.
- **Artifact continuity:** selected files and preview targets are stored per workspace and conversation, then restored when the user returns to that task. Missing files are cleared instead of leaving stale editor state behind.
- **Session continuity:** a Ctrl/Cmd+Tab conversation HUD provides MRU switching across saved workspaces. It loads lightweight conversation summaries and fetches the full transcript only after selection, then routes through the existing loader so session, queue, goal, and artifact state stay together.
- **Activity continuity:** each saved Grok run carries its conversation ID, allowing the switcher and Task Inspector to show verified running, completed, failed, or cancelled states without inferring identity from prompt text or filesystem paths.
- **Coding context:** the composer surfaces the active Git branch and diff summary with direct Review and Files actions, adapting Duck-Agent's coding-status row to this app's existing project snapshot and review routes.
- **Multi-session workspace:** a persisted secondary conversation pane keeps another saved thread visible for comparison or monitoring. It is read-only until focused, and Grok Build still serializes execution through the existing singleton backend.
- **Session dock:** the secondary pane now persists up to four saved conversation tabs, adapted from Duck-Agent session tiles. Tabs remain read-only previews until focused, so execution continues through the active Grok Build conversation and cannot create a second runtime.
- **Worktree visibility:** Duck-Agent's project isolation affordance is adapted into a reversible Worktree toggle beside the active Git branch. It only changes the existing Grok Build execution setting for the next run; it does not create or mutate Git state from the renderer.
- **Worktree overview:** the Git coding row can inspect `git worktree list --porcelain` through a typed bridge and show main, linked, and detached worktrees. A dedicated confirmation flow can create an explicitly named new or existing-branch worktree under `.worktrees/`; removal remains out of scope.
- **Worktree adoption:** an existing linked worktree can be registered as a project and selected from the overview. This is a project-store action only; it never creates, removes, or checks out a Git worktree.
- **Worktree UI QA:** the desktop smoke harness launches an isolated Electron profile and temporary Git fixture to verify the confirmation dialog and real checkout lifecycle.
- **Quick Entry:** a Duck-Agent-inspired global shortcut opens a sandboxed lightweight composer and sends only validated text plus a current/new conversation target back to the main renderer; it never starts a second agent runtime.
- **Workspace attachments:** a Duck-Agent-inspired composer flow lets users attach up to eight files already visible in the safe workspace file rail, either from the rail or by dropping them onto the composer. Native dropped paths are matched against that allowlist before the renderer sends relative workspace paths as prompt context; arbitrary outside-workspace paths and directories are rejected.
- **Composer drafts:** unsent prompt text and attachments are stashed per conversation under `chat.draft.${threadId}` so switching chats or starting a new one does not leak or drop the draft.
- **Queue control:** queued rows can be edited or sent immediately. Stop parks the remaining queue instead of auto-draining the next item; Resume queue or Send now starts the next Grok Build turn.
- **Workspace refresh:** already-open Files and Review panes debounce Grok Build streaming-json tool/phase events and refresh in place. They do not auto-open or steal focus.
- **Action-oriented Git Review:** Duck-Agent's review workbench pattern is adapted into per-file stage/unstage actions, staged-diff fallback, and an explicit confirmation before tracked changes are discarded. All operations stay inside the selected repository through the existing validated workspace bridge.
- **Review synchronization:** the review rail refreshes read-only Git status after Grok Build settles, after a workspace switch, and when the window regains focus. It preserves a selected diff when the path remains changed and ignores stale async results after a workspace switch; it does not poll or mutate Git state automatically.
- **Native completion feedback:** Duck-Agent's separate native-notification channel is adapted for Grok Build completion and failure events. The main process validates and bounds payloads, suppresses duplicates while the workbench is focused, and restores the existing window on notification click; it does not create a second runtime or windowed agent.
- **Live task visibility:** the Task Inspector summarizes the current Grok Build run, goal, queue, and streamed activity without inventing a second approval or execution system.
- **Workspace checklist:** Duck-Agent's explicit todo affordance is adapted into a small per-workspace checklist in the existing Task Inspector. It is user-controlled and persisted through the existing store; Grok Build remains the only execution runtime.
- **Structured activity status:** Duck-Agent's composer status-stack idea is adapted into typed phase events from the existing Grok Build backend. The inspector can distinguish preparation, advisor/MoA consultation, execution, recovery, completion, cancellation, and failure without inferring state from streamed prose.
- **Background work visibility:** scheduled runs now publish running/completed/failed events through the existing Electron bridge. The Scheduled page shows active work, retains the last failure detail, and reuses the existing native notification path; it does not add a second scheduler or agent runtime.
- **Artifact continuity:** Duck-Agent's session artifact index is adapted into a local Artifacts page over Grok Build's persisted conversations. It extracts bounded links, files, and images without adding a gateway or remote media store.
- **Session context rail:** Duck-Agent's right-sidebar workbench pattern is adapted into a single typed coordinator for Files, Terminal, Activity, and Preview. Existing scoped bridges and sandboxed preview behavior remain the source of truth.
- **Imagine UI kit:** sidebar, empty states, chat avatars, and the dock icon use a generated cyan-outline icon set anchored to the hex spark mark. No second brand or lettering inside the glyphs.
- **Searchable model picker:** the composer and Settings replace the native `<select>` with a Hermes-style grouped catalog: provider sections, clean display names, a current-model header, search-to-reveal the rest of the list, refresh, and a Manage providers footer. Models already listed by `grok models` stay selectable. NVIDIA NIM entries are routed through a local stream-compat proxy so Grok Build can parse NIM's `usage: null` chunks.
- **Session-scoped plans:** `plan.md` belongs to the current Grok session. A new chat or workspace does not inherit another session's saved plan. `/view-plan` only reads the active session.
- **Plan decision gate:** the workbench waits for the session's `plan.md` before enabling decisions, then offers View plan, Approve & build, Revise plan, or Reject & dismiss. Only the explicit approval action starts implementation; revision remains plan-only.
- **Session-attached review:** Git Review is available as a context overlay over the active chat, reusing the existing workspace-scoped diff and stage/unstage/discard actions instead of creating a second Git authority.
- **Transcript navigation:** Duck-Agent's jump-to-bottom affordance is adapted to the Grok Build transcript with bounded scroll detection and no change to the streaming backend.
- **Transcript rendering budget:** the newest 40 persisted messages render immediately; older turns remain available through explicit 40-message pages, reducing long-session DOM and Markdown work without losing history.
- **Task-loss protection:** the Electron lifecycle now confirms before quitting an active Grok Build run, adapting Duck-Agent's pure quit-prompt decision pattern while keeping Grok Build as the sole execution runtime.
- **Approval visibility:** the Task Inspector also reports the effective approval mode (automatic, interactive, plan-only, or no-prompts) from the existing Grok Build settings.
- **Terminal continuity:** the chat terminal rail reuses the existing workspace-only command bridge and output cap; it does not add a second shell or broaden command authority.
- **Transient feedback:** lifecycle notifications are emitted by the existing run/queue path and auto-dismiss; the transcript and inspector remain the durable source of truth.
- **Session continuity:** history entries can now be forked into a fresh Grok session while preserving the visible transcript as context.
- **Message branching:** user turns expose **Branch**, which preserves the turns before that instruction, starts a new Grok session, and pre-fills the selected instruction for editing before it runs.
- **Structured activity:** the Task Inspector now groups bounded streamed output into expandable response, reasoning, and error rows, consolidating every reasoning phase from one run into one capped diagnostic row with an update count. Private reasoning is intentionally omitted from the primary chat transcript; the existing Grok phase indicator remains the source of lifecycle truth.
- **Shared reasoning buffer:** reasoning chunks are consolidated before the renderer commits a live event frame, then reused by persisted/reconnected logs and the read-only session dock. This prevents provider phase boundaries from becoming duplicate thinking turns while retaining a bounded diagnostic trace.
- **Ambient workbench state:** a compact status bar adapts Duck-Agent's statusbar pattern to this app's verified state, keeping backend health, workspace/branch, active queue, Git changes, approval mode, selected model, and DuckBot memory availability visible without opening another panel.
- **Durable task admission:** renderer-side startup locking and active-run reconciliation adapt Duck-Agent's active-work guard to the single Grok Build backend, so long-running work remains visible and follow-up prompts queue instead of racing into a singleton error.
- **Native delegation visibility:** Grok Build's documented `spawn_subagent`/`SubagentCompleted` headless envelopes and `subagent_spawned`/`subagent_finished` ACP notifications now feed a compact Task Inspector roster. The renderer never treats child reasoning as public chat output.
- **Performance visibility:** the Task Inspector shows bounded recent input/output token totals and average latency when Grok reports usage. Long conversations refresh a bounded checkpoint automatically, so the next turn does not resend the full visible transcript.
- **Renderer recovery:** a reloaded workbench can request the main process's bounded active-run snapshot, restore the associated conversation and session ID, and continue receiving future events without starting a second Grok process.
- **Run inspection:** Run History now uses persisted thread/session identity for a master-detail inspector with safe conversation opening, session resume, run forking, active-run stop, and bounded diagnostics.
- **Interrupted-run recovery:** The durable run journal preserves bounded phase/event metadata across a main-process restart. Orphaned runs are labeled **Interrupted · outcome unknown** instead of being misreported as user-cancelled; resume/fork remains an explicit user decision.

## Sources checked but not selected as a base

- MiniMax public repositories found during research include [Mini-Agent](https://github.com/MiniMax-AI/Mini-Agent) and OpenRoom. Neither was treated as a drop-in desktop coding-agent backend.
- The official ZCode desktop application source was not found. `Oct1AtJoe/zcode-desktop` is a third-party monitor and is labeled as such.
